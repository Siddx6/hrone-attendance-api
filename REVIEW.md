# REVIEW.md

Review of the starter `app/main.py`. Every item below was fixed in the submitted `app/main.py`.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` at the top | The client is not timezone-aware, so PyMongo returns naive datetimes. Naive and aware values cannot be compared or subtracted, and a naive UTC value looks like local time. | `compute_overtime` builds an IST-aware `end` and subtracts a naive `punch_out` from Mongo: `TypeError: can't subtract offset-naive and offset-aware datetimes` (a 500). | `MongoClient(..., tz_aware=True, tzinfo=timezone.utc)`. All instants are UTC-aware inside the app and converted to epoch ms only at the API boundary. |
| 2 | `health()` | Always returns `{"status": "ok"}` without touching MongoDB. | Stop MongoDB and call `/health`: still 200. The contract wants 503. | Ping MongoDB; on `PyMongoError` return 503. |
| 3 | `create_employee` | Check-then-insert (`find_one`, then `insert_one`) with no unique index. | Ten parallel `POST /employees` with the same `emp_code`: several get 201 and duplicates are stored. | Unique index `uq_emp_code` created at startup; the insert catches `DuplicateKeyError` and returns 409. |
| 4 | `create_employee` | `created_at = datetime.now()` is naive local time, and the response returns the datetime instead of epoch milliseconds. | `created_at` comes back as an ISO string, which breaks the "instants are epoch ms" convention. | Store `datetime.now(timezone.utc)` (ms precision); return epoch ms through `emp_out()`. |
| 5 | `EmployeeIn` | No validation at all: any `emp_code`, email, shift string or `joined_on`; `shift_start == shift_end` allowed. | `{"emp_code":"x","shift_start":"99:99","joined_on":"hello"}` is accepted with 201. | Pattern/length constraints from the contract, a real-calendar-date check for `joined_on`, and a validator that rejects equal shift times (422). |
| 6 | `list_employees` | `skip = page * page_size` skips the first page (page 1 returns the second page of data). | With 3 employees, `?page=1&page_size=20` returns an empty list. | `skip = (page - 1) * page_size`. |
| 7 | `list_employees` | `total = count_documents({})` ignores the department filter; results are unsorted; `page`/`page_size` are unvalidated (`page=0` gives a negative skip and a server error; `page_size=100000` is allowed). | `?department=Eng` shows `total` of the whole collection. | `count_documents(q)` with the same filter, sort by `emp_code`, `page >= 1` and `1 <= page_size <= 100` (422 otherwise). |
| 8 | `punch_in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError` (500). | Punch in with `emp_code: "NOPE"`. | `get_employee()` returns 404 first. |
| 9 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` produces naive *server-local* time, and `ts.date()` is a local date, not the IST date (R1). Microseconds are kept (R1 says truncate to whole seconds). `if body.punched_at` also treats a falsy value as missing. | On a UTC server, a punch at 02:00 IST on the 7th is stored with date 6th. A punch at 09:40:00.900 keeps the fraction. | `ms_to_dt()` (UTC, truncated to seconds); the date comes from `attendance_date()` (IST, with the overnight-shift rule); `is not None` checks. |
| 10 | `punch_in` / `PunchInIn` | `status: str` accepts anything, including `ABSENT`, `LEAVE` or garbage; `punched_at` accepts floats/strings/seconds-looking values. | `{"status":"ABSENT"}` returns 201. `punched_at: 1783312500` (seconds) is accepted. | `Literal["PRESENT","WFH","ON_DUTY"]`; `punched_at` is a strict int in `[100000000000, 4102444800000]`. |
| 11 | `punch_in` | Check-then-insert race and no unique index on `(emp_code, date)`. | Ten parallel identical punch-ins: more than one 201 and duplicate records for the day. | Unique index `uq_emp_date`; `insert_one` catches `DuplicateKeyError` and returns 409, so exactly one request wins. |
| 12 | `compute_late_minutes` | (a) The 10-minute grace is tested on whole minutes: `minutes > 10` after `int()`, so 09:40:01 gives 0 instead of 10. (b) The shift start is built with `punch_in.replace(hour, minute)` on whatever timezone the datetime carries (UTC from Mongo), not IST. (c) Overnight shifts: the start is put on the punch-in's own date, so a 01:00 IST punch-in for a 22:00 shift gets a start in the future and returns 0. (d) No truncation to whole seconds. | Shift 09:30, punch-in 09:40:01 IST: returns 0, R2 says 10. Punch-in 09:35 IST stored as 04:05 UTC: start becomes 09:30 UTC, result 0. | `compute_late_minutes(punch_in, date, shift_start)`: the start is an IST datetime on the attendance date; compare **seconds** against 600; then floor to minutes. |
| 13 | `compute_work_hours` | Python's `round()` is banker's rounding on a binary float (9.125 gives 9.12); R4 says half-up. No truncation to whole seconds. | 9h07m30s: `round(9.125, 2)` returns 9.12, expected 9.13. | `Decimal(seconds) / Decimal(3600)` quantized with `ROUND_HALF_UP`. |
| 14 | `compute_overtime` | (a) Naive/aware subtraction raises `TypeError` (see #1). (b) No 30-minute minimum (R3): 5 minutes counts as overtime. (c) The shift end is always on the record date, wrong for overnight shifts. (d) `int()` truncates toward zero instead of flooring. | Sample 1 (punch-out 18:35) would report 5 overtime minutes; an overnight record gets a negative or wrong value. | `compute_overtime(punch_out, end)` with `end` from `shift_end_dt()` (next day for overnight shifts), floor to minutes, return 0 below 30. |
| 15 | `punch_in` response | Returns `id` (the Mongo ObjectId as a string) and raw datetimes; `_id` must never appear and instants must be epoch ms. | Response contains `"id": "6acc..."` and `"punch_in": "2026-07-14T04:02:00"`. | `record_out()` builds the response explicitly: no `_id`, epoch ms, defaults filled. |
| 16 | `list_attendance` | Loads the **entire collection** into memory (`find(q)` then Python sort and slice). Sorts only by `date` (no `emp_code` tie-break, so pages are not stable). | At 100,000 records every request reads and sorts everything; page boundaries can repeat or skip rows. | `find(q).sort(date desc, emp_code asc).skip().limit()` backed by index `date_emp`; `total` from `count_documents(q)`. |
| 17 | `list_attendance` | No validation of `date_from`/`date_to`/`status`; `date_from > date_to` is not rejected; `page=0` gives a negative slice; leaks `id`; legacy documents without `half_day`/`history` come back without those fields. | `?date_from=hello`, `?status=XYZ`, `?page=0`. Sample record 9 has no `half_day` or `history`. | Typed query params (`DateStr`, `Status`), explicit 422 for `date_from > date_to`, `record_out()` fills `half_day=false` and `history=[]`. |
| 18 | whole app | No indexes. | Any filter or sort at scale is a collection scan (`COLLSCAN` in explain). | `ensure_indexes()` at startup (idempotent): see DECISIONS.md. |
| 19 | history values | The starter returns BSON dates inside `history[].at` / `changes` unconverted. | Sample record 8 shows `"at": "2026-07-08T05:00:00"`. | `history_out()` converts every datetime to epoch ms, including `from`/`to` inside `changes`. |

## Looked at and decided it was fine

* `load_dotenv()` at import: by default it does **not** override variables that are already set, so real environment variables win, as the contract requires.
* The `IST = timezone(timedelta(hours=5, minutes=30))` constant is correct (India has no DST). I kept it.
* Default `MONGO_URI` / `MONGO_DB` fallbacks are only for local development; the grader's environment variables take priority.
* Returning `201` for create/punch-in is what the contract specifies.
